# account-template-ui

Шаблон фронтенда личного кабинета: React 19 + TypeScript + Vite, MUI, react-router, react-query,
zustand, i18next. Реализован вертикальный срез Auth API — вход, регистрация, подтверждение операций
цепочкой звеньев, резервный вход при утрате доступа к почте, профиль, настройки, смена емаила и
телефона, двухфакторная защита (пароль или TOTP, аварийные коды) и список сессий. Интерфейс переключается между русским и английским.

Функциональность собирается из модулей: модуль объявляет свои роуты, навигацию, JSON-схемы экранов
и переводы, а реестр (`src/app/modules.ts`) складывает из них приложение — ядро при подключении
нового модуля не меняется.

В деве бэкенд изображает MSW (`src/mocks/handlers.ts`): операции, сессии и профиль лежат в памяти
страницы и возвращаются к исходному состоянию при её перезагрузке. Всё, что описано ниже про
тестовые логины, коды и флаги, — поведение этих моков, а не контракт бэкенда.

| Маршрут              | Что это                                                                     |
| -------------------- | --------------------------------------------------------------------------- |
| `/signin`            | Вход по емаилу или телефону                                                 |
| `/signin/recovery`   | Резервный вход, когда доступа к почте нет                                   |
| `/signup`            | Регистрация по емаилу                                                       |
| `/confirm`           | Подтверждение входа и регистрации (код из письма, второй фактор)            |
| `/profile`           | Личные данные, кабинеты, полоса двухфакторной защиты                        |
| `/settings`          | Язык и часовой пояс профиля, смена емаила и телефона, управление 2FA        |
| `/sessions`          | Открытые сессии выбранного кабинета, закрытие одной или нескольких          |
| `/security/password` | Установка пароля вторым фактором                                            |
| `/security/totp`     | Подключение приложения-генератора (QR и секрет строкой)                     |
| `/security/confirm`  | Подтверждение операций защиты: 2FA, аварийные коды, смена емаила и телефона |
| `/security/codes`    | Показ выданных аварийных кодов и их перевыпуск                              |
| `/demo`              | Демо-модуль: пример подключения экрана через реестр                         |

## Запуск

Нужен Node ≥ 22.12 (в `.nvmrc` — 22.23.1).

```bash
npm ci
npm run dev -- --host
```

Моки в деве поднимаются сами, отдельного флага для этого не нужно. `--host` нужен, только если
страницу открывают с другого устройства в сети.

Флаги отладки задаются в строке запуска (`VITE_MOCK_2FA=TOTP npm run dev`) или в `.env` — Vite
читает их на старте, так что смена флага требует перезапуска сервера. Назначение и мотивация
каждого флага подробно расписаны в `.env.example`.

Против живого бэкенда: `VITE_ENABLE_MOCKS=0` и `VITE_AUTH_API_BASE_URL` с адресом API. В сборке
с `mode=production` код подъёма моков вырезается, и `1` там ничего не включает.

Остальные команды: `npm run build`, `npm run preview`, а перед коммитом —
`npm run typecheck && npm run lint && npm test`.

## Что вводить

Секреты в моках постоянные. Каждый из них печатается в консоль браузера с префиксом `[MSW]` в момент,
когда операция доходит до соответствующего звена, — подсматривать в этот файл не обязательно.
Исключение одно: код генератора при подключении TOTP печатается сразу при создании операции, потому
что вместе с ней рождается и сам секрет генератора.

| Звено                  | Значение            | Где спрашивают                                                                                                           |
| ---------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Код из письма          | `183947`            | `/confirm` после входа и регистрации; `/security/confirm` — смена емаила (код и на текущий, и на новый адрес) и телефона |
| Пароль (второй фактор) | `MockPass2026!`     | `/confirm` и `/security/confirm`, когда второй фактор аккаунта — пароль                                                  |
| Код генератора (TOTP)  | `246810`            | `/confirm` и `/security/confirm`, когда второй фактор аккаунта — TOTP; `/security/totp`                                  |
| Аварийный код          | `RECOVRY1-CODE0011` | резервный вход; смена емаила без доступа к нему; вместо второго фактора — при обычном входе и отключении 2FA             |

Зарезервированные значения — ветки ошибок, которые иначе руками не получить:

| Значение                 | Где                                    | Что получаем                                                      |
| ------------------------ | -------------------------------------- | ----------------------------------------------------------------- |
| `nobody@example.com`     | `/signin`, `/signin/recovery`          | 400 «пользователь не найден», ошибка садится под поле логина      |
| `taken@example.com`      | `/signup`; смена емаила на `/settings` | 400 «емаил уже занят» под полем емаила                            |
| `+7 900 000 00 00`       | смена телефона на `/settings`          | 400 «номер уже занят» под полем номера; сравниваются только цифры |
| `inprogress@example.com` | `/signup`                              | 429 «заявка уже обрабатывается» — общий алерт, поле не краснеет   |

Ещё одна ветка без флага: часовой пояс «(UTC-12:00) Линия перемены дат» на `/settings` сервер
«не знает», и сохранение возвращает 400 по полю `tz`.

Демо намеренно тесное, чтобы тупиковые ветки достигались за пару кликов: 3 попытки на звено,
2 повторные отправки кода, 600 секунд на операцию. Исключение — подтверждение нового адреса при
смене емаила: оно живёт 72 часа, и к нему возвращаются из карточки емаила на `/settings`.

Пароль, заданный на `/security/password`, мок не запоминает: проверяет он только схему и надёжность,
а звено пароля дальше всё равно ждёт `MockPass2026!`.

## Сценарии отладки

Флаг `VITE_MOCK_2FA` задаёт только стартовое состояние второго фактора, чтобы не проходить его
включение руками: дальше пароль или TOTP включаются, коды перевыпускаются и 2FA отключается из
карточки на `/settings`.

```bash
# 2FA выключена (как у свежего аккаунта) — синий щит, призыв «включить»
npm run dev -- --host

# Пароль как второй фактор — жёлтая полоса, призыв «усилить»
VITE_MOCK_2FA=PASSWORD npm run dev -- --host

# TOTP — зелёная полоса, верхняя ступень
VITE_MOCK_2FA=TOTP npm run dev -- --host

# TOTP + предупреждение об остатке кодов (жёлтое)
VITE_MOCK_2FA=TOTP VITE_MOCK_RECOVERY_CODES=3 npm run dev -- --host

# TOTP + «остался последний код» (красное)
VITE_MOCK_2FA=TOTP VITE_MOCK_RECOVERY_CODES=1 npm run dev -- --host

# TOTP + «коды кончились» (красное)
VITE_MOCK_2FA=TOTP VITE_MOCK_RECOVERY_CODES=0 npm run dev -- --host

# Одиночный кабинет — в профиле нет карточек кабинетов, на /sessions нет выбора кабинета
VITE_MOCK_MULTI_REALM=0 VITE_MOCK_2FA=PASSWORD npm run dev -- --host

# Код принят, а войти не удалось: 429 по лимиту сессий — экран прячет поле кода и предлагает «Повторить»
VITE_MOCK_SESSION_LIMIT=1 npm run dev -- --host

# Сервер не знает английский: выбрать «English» на /settings → Сохранить → 400 по полю lang
VITE_MOCK_REJECT_LANG=1 npm run dev -- --host

# Новый емаил заняли, пока шла смена: код с нового адреса принят → тупик «адрес уже занят»
VITE_MOCK_EMAIL_CONFLICT=1 npm run dev -- --host

# /security/password: оценка надёжности не пришла — шкала серая, кнопка повтора, «Продолжить» закрыта
VITE_MOCK_PASSWORD_STRENGTH_FAIL=1 npm run dev -- --host

# /security/password: генератор пароля не ответил — поле прежнее, под кнопкой объяснение
VITE_MOCK_GENERATE_PASSWORD_FAIL=1 npm run dev -- --host

# /security/totp: QR не пришёл — плита с причиной и повтором, секрет строкой раскрыт сам
VITE_MOCK_TOTP_QR_FAIL=1 npm run dev -- --host

# /security/totp: секрет строкой не пришёл — отказ на месте значения, QR работает
VITE_MOCK_TOTP_SECRET_FAIL=1 npm run dev -- --host
```

Про значения флагов:

- `VITE_MOCK_2FA` — `PASSWORD` или `TOTP`, пусто (по умолчанию) значит «2FA выключена». Флаг задаёт
  только точку старта: обычному входу включённый фактор добавляет второе звено после кода из письма,
  резервному — выбирает первое звено цепочки.
- `VITE_MOCK_RECOVERY_CODES` — целое ≥ 0, по умолчанию 8. Без включённой 2FA не действует: остаток
  аварийных кодов приходит в профиль только вместе со вторым фактором. Предупреждение на полосе
  защиты в `/profile` есть на остатке 0, 1 и 2..3, при 4 и больше его нет вовсе; карточка 2FA на
  `/settings` показывает остаток всегда. Флаг только сокращает путь — принятый аварийный код
  убавляет остаток, так что до нуля можно дойти и руками.
- `VITE_MOCK_MULTI_REALM` — `0` оставляет пользователю один кабинет; по умолчанию их два.
- `VITE_MOCK_SESSION_LIMIT` — `1` отклоняет первое открытие сессии по подтверждённой операции
  (429, Retry-After 30 с), повтор проходит. По умолчанию выключен.
- `VITE_MOCK_REJECT_LANG` — `1` заставляет сервер отвергать явный английский язык профиля.
  По умолчанию выключен, иначе в демо нельзя было бы сохранить английский. На язык интерфейса
  не влияет: им управляет переключатель в шапке.
- `VITE_MOCK_EMAIL_CONFLICT` — `1`: применение второй операции смены емаила отвечает «адрес уже
  занят». Руками эту гонку не получить — адрес проверяется ещё на первом шаге. По умолчанию выключен.
- `VITE_MOCK_PASSWORD_STRENGTH_FAIL`, `VITE_MOCK_GENERATE_PASSWORD_FAIL`, `VITE_MOCK_TOTP_QR_FAIL`,
  `VITE_MOCK_TOTP_SECRET_FAIL` — `1`: соответствующая ручка (оценка пароля, генератор пароля, QR и
  секрет заготовки TOTP) отвечает 500. По умолчанию выключены.

Сценарии, для которых хватает последовательности действий, без флагов:

1. `/signup` с `inprogress@example.com` → общий алерт про заявку (429), поле не краснеет.
2. `/signup` с `taken@example.com` → пауза на проверке логина, ошибка садится под поле емаила,
   кнопка заблокирована.
3. `/signin` → неверный код (например `000000`) → ошибка под полем со счётчиком оставшихся попыток;
   верный `183947` → вход проходит. В Network видно, что завершающий `POST /v1/session` уходит уже
   без `secret`.
4. `/settings` → выбрать «(UTC-12:00) Линия перемены дат» → Сохранить → 400 подсвечивает селект
   часового пояса.
5. `/sessions` → переключение кабинета работает, список грузится, текущая сессия помечена.
6. `/signin/recovery` → цепочка из двух звеньев: сперва второй фактор (`246810` при `VITE_MOCK_2FA=TOTP`,
   иначе `MockPass2026!` — в том числе когда 2FA выключена), затем аварийный код `RECOVRY1-CODE0011`.
7. Обычный вход при включённой 2FA: на звене второго фактора вместо пароля или TOTP принимается
   аварийный код. Такая замена разрешена только там, где она объявлена, — на входе и при отключении
   2FA; перевыпуск кодов и привязка генератора требуют именно свой секрет.
8. Тупики: трижды ввести неверный секрет, дважды запросить повторную отправку, дождаться истечения
   операции, нажать «Отменить» — экран возвращает туда, откуда операция начиналась.
9. Включение 2FA при выключенной: `/settings` → карточка 2FA → пароль → `/security/password`
   (пароль, прошедший оценку надёжности) → `/security/confirm`, код `183947` → `/security/codes`
   с набором аварийных кодов. TOTP: та же карточка → `/security/confirm`, код `183947` →
   `/security/totp`, код генератора `246810` → `/security/codes`.
10. Смена емаила: `/settings` → карточка емаила → новый адрес → `/security/confirm`, код `183947`
    с текущего адреса (при включённой 2FA следом её звено) → код `183947` с нового адреса. Со
    второго шага можно уйти и вернуться к нему из той же карточки.
11. Смена телефона: `/settings` → карточка телефона → номер → `/security/confirm`, код `183947`
    с емаила (при включённой 2FA следом её звено) → номер сохранён.
